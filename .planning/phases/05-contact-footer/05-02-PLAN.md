**State:**
```typescript
type FormState = { name: string; email: string; budget: string; project: string };
const EMPTY: FormState = { name: "", email: "", budget: "", project: "" };

export default function ContactSection() {
  const ctx = useContext(GlobalContext);
  const profile = ctx?.profile;

  const [form, setForm] = useState<FormState>(EMPTY);
  const [sending, setSending] = useState(false);
  const [sent, setSent] = useState(false);
  const [error, setError] = useState<string | null>(null);

  useEffect(() => {
    if (!sent) return;
    const t = setTimeout(() => {
      setSent(false);
      setForm(EMPTY);
    }, 3500);
    return () => clearTimeout(t);
  }, [sent]);
```

**Submit handler:**
```typescript
  const handleSubmit = async (e: React.FormEvent) => {
    e.preventDefault();
    setSending(true);
    setError(null);
    try {
      const res = await fetch("/api/contact", {
        method: "POST",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify(form),
      });
      if (!res.ok) throw new Error("non-2xx");
      setSent(true);
    } catch {
      setError("Something went wrong — try again.");
    } finally {
      setSending(false);
    }
  };
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User form input → fetch POST | User-supplied text from controlled inputs crosses to the API route |
| GlobalContext.profile → UI | CMS data read by the component — read-only, no mutation |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-06 | Tampering | ContactSection form — client-side input before POST | accept | Client-side is UX only; server-side validation in route.ts is the trust boundary (T-05-01 in Plan 01). No validation logic duplicated here since failure cases are handled by the server response. |
| T-05-07 | Information Disclosure | profile.email / linkedInUrl / githubUrl rendered in DOM | accept | These are intentionally public contact details authored in Sanity. Not PII in a privacy-sensitive sense — they are the purpose of the section. |
| T-05-08 | Denial of Service | Form allows rapid re-submission (button re-enabled after success reset) | accept | `disabled={sending}` prevents double-submit during in-flight request. Post-success cooldown of 3.5s is UX only. Server-side rate limiting is Resend's responsibility (5 req/s). Sufficient for portfolio use case. |
</threat_model>
