<objective>
Establish the CSS foundation that all responsive and accessibility work in Waves 2 and 3 depends on. This plan adds four things to `app/globals.css`: (1) a `@theme` block with custom `--breakpoint-ms` (760px) and `--breakpoint-compact` (480px) variables so Tailwind generates `ms:` and `compact:` prefix utilities, (2) a `.focus-ring` utility class that applies the 2px orange `:focus-visible` ring, (3) a `.sr-only` utility class for visually-hidden screen-reader text, and (4) an extended `@media (prefers-reduced-motion: reduce)` rule that adds `.ms-pulse-anim` and `.ms-cursor-anim` selectors to cover inline-style animations that the existing rule does not reach.

Purpose: No responsive or accessibility class added in Waves 2 and 3 will work until these CSS foundations exist. All other plans depend on this one.

Output: Modified `app/globals.css` — no new files, no component changes.
</objective>

## Task 1.1 — Add @theme custom breakpoints

**Type:** implementation
**File:** `app/globals.css`

**Action:**

Add a top-level `@theme` block to `app/globals.css`. It must be placed **outside** any `@layer` block — place it immediately after the `@config` and `@plugin` directives on lines 2–3, before the `@custom-variant dark` line.

Insert the following block between line 3 (`@plugin "tailwindcss-animate";`) and line 5 (`/* Override Tailwind dark variant...`):

```css
@theme {
  --breakpoint-ms:      760px;
  --breakpoint-compact: 480px;
}
```

`--breakpoint-ms` generates an `ms:` utility prefix that fires at viewports >= 760px (min-width). `--breakpoint-compact` generates a `compact:` prefix that fires at >= 480px. Both work identically to Tailwind's built-in `sm:`/`md:` prefixes.

Do NOT place this block inside `@layer base`, `@layer utilities`, or any other `@layer` rule — Tailwind v4 requires `@theme` to be top-level.

**Verify:**
- [ ] `grep -n "@theme" app/globals.css` returns a line with `@theme {`
- [ ] `grep -n "breakpoint-ms" app/globals.css` returns `--breakpoint-ms:      760px;`
- [ ] `grep -n "breakpoint-compact" app/globals.css` returns `--breakpoint-compact: 480px;`
- [ ] `npm run build` exits 0 (no Tailwind parse error)

**Acceptance criteria:**
- `@theme` block is top-level (not nested inside any `@layer`)
- Both `--breakpoint-ms` and `--breakpoint-compact` variables are present
- Build succeeds with no errors

## Task 1.2 — Add .focus-ring and .sr-only utility classes

**Type:** implementation
**File:** `app/globals.css`

**Action:**

Extend the existing `@layer utilities` block at the bottom of `app/globals.css` (currently lines 190–194, containing only `.text-balance`). Add `.focus-ring` and `.sr-only` inside that same block:

```css
@layer utilities {
  .text-balance {
    text-wrap: balance;
  }

  .focus-ring {
    outline: none;
  }
  .focus-ring:focus-visible {
    outline: 2px solid var(--ms-orange);
    outline-offset: 2px;
    border-radius: var(--radius-sm);
  }

  .sr-only {
    position: absolute;
    width: 1px;
    height: 1px;
    padding: 0;
    margin: -1px;
    overflow: hidden;
    clip: rect(0, 0, 0, 0);
    white-space: nowrap;
    border-width: 0;
  }
}
```

Notes:
- `.focus-ring` sets `outline: none` on the base element so the browser default does not show. The `:focus-visible` rule then adds the design-system orange ring. This does NOT conflict with `style={{ all: "unset" }}` on buttons — inline styles do not apply to pseudo-classes, so `:focus-visible` styles from a class are unaffected by `all: "unset"` in inline style.
- `.sr-only` visually hides content (1px box, clipped) while keeping it in the accessibility tree. Used for the `aria-live` region in Plan 06-03.
- Both classes go inside `@layer utilities` so Tailwind includes them in the output and they are overridable by other utilities.

**Verify:**
- [ ] `grep -n "focus-ring" app/globals.css` returns lines with `.focus-ring` and `.focus-ring:focus-visible`
- [ ] `grep -n "sr-only" app/globals.css` returns a line with `.sr-only`
- [ ] `grep -n "ms-orange" app/globals.css | grep focus` confirms the focus ring uses `var(--ms-orange)`
- [ ] `npm run build` exits 0

**Acceptance criteria:**
- `.focus-ring` applies `outline: none` to the element and a 2px orange outline on `:focus-visible`
- `.sr-only` hides content visually using the standard clip pattern
- Both classes are within `@layer utilities`

## Task 1.3 — Extend prefers-reduced-motion rule

**Type:** implementation
**File:** `app/globals.css`

**Action:**

The existing reduced-motion rule at line 160 currently reads:

```css
@media (prefers-reduced-motion: reduce) {
  .animate-pulse, [class*="ms-cursor"] { animation: none; }
}
```

This covers class-based animations but NOT inline `style={{ animation: "ms-pulse..." }}` values used on three elements: the `StatusDot` inner pulse span, the `FooterSection` status dot pulse span, and the `ExperienceSection` current-role dot. The inline `animation:` style has higher CSS specificity than a class rule — `!important` is required to override it.

Replace the existing rule with:

```css
@media (prefers-reduced-motion: reduce) {
  .animate-pulse,
  [class*="ms-cursor"],
  .ms-cursor-anim,
  .ms-pulse-anim {
    animation: none !important;
  }
}
```

The `!important` is required and intentional — it is the standard pattern for overriding inline-style animation values from a media query. Without it, `animation: "ms-pulse..."` set via React's `style` prop cannot be stopped by a CSS class rule.

The class names `.ms-pulse-anim` and `.ms-cursor-anim` will be added to elements in Plans 06-02 and 06-03. Adding the CSS rule first (Wave 1) means the selectors are ready when the class names appear on elements.

**Verify:**
- [ ] `grep -n "ms-pulse-anim" app/globals.css` returns a line within the `@media (prefers-reduced-motion)` block
- [ ] `grep -n "!important" app/globals.css` returns a line in the reduced-motion rule
- [ ] `npm run build` exits 0
- [ ] `npm run lint` exits 0

**Acceptance criteria:**
- Existing `.animate-pulse` and `[class*="ms-cursor"]` selectors are preserved
- `.ms-cursor-anim` and `.ms-pulse-anim` are added to the same rule
- `animation: none !important` is the declaration (not `animation: none`)
- The rule remains inside `@media (prefers-reduced-motion: reduce)`
